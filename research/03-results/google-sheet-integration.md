# 구글시트 기반 학생 데이터 연결 프로토타입

## 목적과 실제 구현

2026-10-25, 학교 학사 API 접근이 불가능한 현재 단계에서 수정 가능한 구글시트를 데이터 편집 원본으로 사용하도록 구현했다. 향후 학교 API·Excel/CSV와 연결할 데이터 계약을 명확히 하고, 수정한 자료가 어드바이징 화면에 전달되는 경로를 기술적으로 점검하는 목적이다. 실제 학생 자료를 확보하거나 학교 API를 연계한 결과는 아니다.

## 데이터 원본과 계약

- 구글시트: https://docs.google.com/spreadsheets/d/1o363_FWYDARmI6vg8ZTRMf4SNF2WMKM-FhRJJV-5nfw/edit
- Students 탭 ID:1874736550. 합성20,000건·28개 필드. 첫 행 헤더와 마지막 SYN-0020000 행을 확인했다.
- 초기 active 행256건. 표시 대상을 active로 선택하며 최소1명·최대1,000명으로 제한한다. 이 한도는 보호 설정이며 최대 부하 검증 결과가 아니다.
- Guide 탭에 편집·범위·동기화·합성 한계를 정리했다. 상태 열에는 Good/Warning/Request/Waiting 네이티브 드롭다운을 설정했다. 헤더·식별열 고정, 숫자 형식·열 너비를 확인하고 네이티브 변환 후 다시 내보낸 워크북의 두 탭을 렌더링해 확인했다.
- 입력: 식별자·학과·학년·대표/선택 모듈·모듈/전체 학점·GPA·점수·상담 상태·진로·성찰·변경 사유·선수요건·계획학점·합성 구분 등. 이수율은 학점으로 계산한다.
- 같은28개 헤더를 사용하는 Excel/CSV를 시트에 가져올 수 있다. 현재 앱의 임의 Excel 파일 직접 업로드 기능은 구현하지 않았다.

## 동기화 경로

구글시트 편집·저장 → Google CSV 읽기 → Vercel GET /api/students → 제약 검증·Student 계약 변환·원본 SHA-256 → React 공통 상태 → 대시보드·학생 목록·상세·상담·모듈별 인원·예시 네트워크.

- 앱 최초 접속, 사용자의 지금 동기화, 활성 화면60초 주기로 읽는다. 숨겨진 탭은 주기 요청을 멈추고 다시 표시될 때 확인한다.
- 단방향 읽기 전용이다. 앱의 상담 입력을 시트에 저장하는 기능·학교 API·웹훅 push·양방향 동기화는 이번 구현에 포함하지 않았다.
- API·CDN 캐시를 비활성화했지만 실제 반영 지연은 Google 응답·네트워크에 의존한다. 정확히60초 이내 반영을 보장하지 않는다.
- 식별자·중복·합성 표시·활성 인원·숫자·학점·모듈·날짜를 검증하고 오류가 있으면 새 snapshot 전체를 거부한다. 오류의 행 번호는 완전히 빈 행을 제외한 CSV 데이터 행 기준이다.
- 최초 연결 실패 시 내장 합성 데모라는 출처를 표시한다. 성공 후 오류가 발생하면 열린 화면의 마지막 정상 snapshot을 유지하고 오류·마지막 확인/반영 시각을 표시한다. 이전 세션 snapshot은 영속 저장하지 않는다.
- 상세 선택은 객체 복사가 아닌 ID 참조로 바꾸어 수정값을 열려 있는 학생 상세에도 전달한다. 학생이 삭제되거나 active에서 제외되면 해당 상세를 닫는다.

## 검증 상태

- 데이터 변환·CSV 인용/개행·잘못된 숫자/날짜·중복·합성 제한·인원 한도·접근 실패·HTTP 읽기 전용/캐시 정책의6개 자동 테스트를 통과했다.
- TypeScript 및 Vite 프로덕션 빌드 통과. 번들 크기 경고는 기존 최적화 과제로 유지한다.
- **모의 API 응답을 사용하는 브라우저 검사**에서60초 갱신, 수동 재시도, 상세의 이름/GPA 갱신, 오류 시 정상 자료 유지, 선택 학생 삭제 시 상세 닫힘, 학생 수/목록/관계 노드255건 일치, 모듈 분석·모바일·최초 실패 출처 안내를 확인했다.
- 실제 구글시트로의 업로드·네이티브 구조·20,000번째 행·편집 가능 문서와 안내는 확인했다.
- **실제 외부 읽기 연결은 권한 확인 단계다.** 사용자에게 링크 뷰어 설정을 요청했고 최초 완료 응답 이후에도 Drive의 shared=false·소유자 권한만 확인되었으며 익명 edit/gviz/export 요청은401이었다. 사용자에게 설정 저장을 재확인하도록 요청했다. 실제 시트 수정 → API → 앱 갱신의 왕복 확인은 아직 완료로 기록하지 않는다.

## 보안 범위와 학교 API로의 확장

이번 공개 데모에는 완전 합성 자료만 사용하며 링크 열람은 읽기 전용으로 한다. 소유자의 편집권한과 공개 독자의 열람권한을 구분한다. 합성 플래그·가상 식별자 검사는 개인정보의 우발 입력을 완전히 방지하지 못하므로 실제 학생 자료는 입력하지 않는다.

실자료 단계에서는 학교 API 또는 서버 인증이 있는 비공개 시트로 교체하고, 사용자 인증·지도학생 조회 범위·역할·접근 기록·동의/기관 절차를 함께 설계한다. 공통 Student 계약 앞의 데이터 어댑터를 교체해 UI와 데이터 취득 경로를 분리한다. 이번 시트 연결 구현을 실제 학사 연동·보안 검증 완료나 교육적 효과의 근거로 사용하지 않는다.
