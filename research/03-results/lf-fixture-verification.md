# LF 시각화 개발 검증과 요구조사 준비 상태

## 실제 수행일과 일정 구분

2026-10-27 오전 자동 작업에서 LF 출력 준비와 요구조사 코드북 초안을 수행했다.10월26일에 완료한 것으로 소급하지 않는다. 오늘 일정의 LF 시각화는 개발용 가상 fixture 그림까지 확인했으며 실제 요구조사 결과 그림은 원자료·도구·기관 절차가 확인되지 않아 미완료다.10월30일 핵심 기능 우선순위도 실제 분석 없이 확정하지 않는다.

## 산출 그림과 값

![가상 계산 검증용 LF 그림: 실제 응답자0명, 기능 우선순위나 교육효과의 근거가 아님](research/figures/lf-development-fixture.png)

그림은 가상ID4개×항목3개12행으로 계산한 좌표만 표시한다. A=(4.50,2.50), B=(3.00,1.00), C=(2.00,−1.00)이며 분할선은 x=3.166667, y=0.833333이다. A HH·B LH·C LL은 계산·시각화 확인용이며 실제 기능 문항R01–R12에 연결하지 않았다. p값·신뢰구간·효과크기나 실제 요구 순위를 산출하지 않았다.

재현: scripts/analyze-needs.py → summary.json → scripts/render-lf-fixture.py → ReportLab SVG. Google Docs와 일반 브라우저에서 읽기 위한 PNG는 해당 SVG를 Edge로 렌더링한 것이다. SVG/PNG 모두 합성·개발용·실제 응답자0명 문구가 그림 안에 포함된다. 원본은 research/figures/lf-development-fixture.svg, PNG는 같은 이름의.png이다.

## 검증 결과

웹앱 로컬 화면에서1440px/390px 너비로 문서 선택·실제 PNG 로드(원본1520px)·그림 대체텍스트·코드북 항목R12를 확인했고 가로 넘침이 없었다. Google Docs에도 그림을 삽입하고 PDF14쪽의 그림7쪽과 기존 필요성·목적2–5쪽, 참고문헌마지막13–14쪽을 확인했다. 그림 단위 검사는 저장소의 공개 CSV를 직접 읽어 실행하므로 개인 생성 폴더 없이도 동작한다.

기존 입력/산술 검사7개를 다시 통과했고 새 그림 검사3개를 통과했다. 새 검사는 합성 문구·수작업 좌표·분할선 표기, 실제/미표시 자료 거부, 비유한 수와 축 범위 밖 거부를 확인한다. 브라우저 렌더링 이미지를 확인하여 축·점·라벨이 잘리거나 서로 겹치지 않음을 점검했다. 검사 중 문자열을 bytes로 가정한 테스트 오류를 수정한 뒤3개가 모두 통과했다.

## 조사 코드북

[교수자·학생 요구조사 코드북 초안](../02-methods/needs-codebook-draft.md)에12개 단일 기능 문항과 필요/현재 지원수준 응답 안내, 모름/결측 처리, 집단별 분석·비공개 자료 계약·실시 전 검토 목록을 준비했다. 이는 문항 확정·내용타당성 검증·IRB 승인 또는 조사 실시를 뜻하지 않는다. 실제 응답자는0명이며 운영 합성 학생 원자료는 수정하지 않았다.
