### 가. 개발용 모의 분석 자료 — 실제 FGI 결과 아님
본 절의 추가 내용은 가상의 전문가 프로필 9개와 프로필별 모의 서면 응답 8개, 총72개 구절을 생성하여 질문·코딩·설계 요구의 연결을 점검한 개발용 예시이다. 전공과 전문분야 및11–27년의 경력은 모두 임의 설정이며 확인된 실제 전문가의 경력이 아니다. 실제 전문가의 모집·동의·FGI·녹음·전사·검토는 실시하지 않았다. 실제 전문가·조사 응답자·평가 참여자는0명이다.
각 구글문서와 응답 구절에 합성 표시 및SYN-E01-Q01형식의 고유ID를 부여하였다. 기존 FGI질문지를 참고하여 현재 업무, 필요 자료, 기능 검토, 기록, 인간 판단, 화면/자료 보호, 예외, 문항/검증의8개 가정형 질문으로 구성하였다. 개인별 서면 형식을 모사한 문서이며 집단 토론의 상호작용 자료가 아니다. 따라서 본 분석을 실제 FGI 결과나 전문가의 합의로 해석하지 않는다.

나. 초기 코딩과 추적 절차
자료 생성과 같은AI작성 과정에서 학사 기준·출처(C01),상담 기록 연속성(C02),목표·성찰·선택(C03),제안 근거·인간 판단(C04),자료 품질·오류(C05),접근 범위·보호(C06),사용자경험·접근성(C07),측정·검토·평가 경계(C08)의8개 초기 범주를 부여하였다. 동일 생성자의 관점과 사전 범주가 반영되므로 범주가 실제 현장에서 독립적으로 출현했다고 주장하지 않는다.
각 답변에는 복수 코드를 허용하고, 같은 문서의 동일 코드는 문서수에서 중복 계산하지 않았다. 범주별 모의문서 수와 구절수는 코드/원문의 연결을 점검하는 기술값이다. 실제 전문가 동의율·요구 강도·이론적 포화도·코더 간 신뢰도가 아니다. scripts/analyze-synthetic-expert-scenarios.cjs로9개프로필·서로 다른10년 이상 가정경력·72개고유구절·코드값/합성표시를 확인하였다.

다. 합성 구절에 기초한 요구 후보의 해석
모의 교육과정/보건 관점에서는 이수율을 졸업 또는 실습 적격의 확정 근거로 확대하지 않고 적용 규정과 판단 유보 조건을 분리하도록 제안하였다(SYN-E02-Q02,SYN-E08-Q01). 이에REQ-M01을 기준/출처/판정 범위의 검토 후보로 연결하였다. 이는 실제 담당자의 규정 대조를 대신하지 않는다.
모의 상담/기술 관점에서는 목표·변경·성찰과 상담의 저장/재조회가 연결되어야 한다는 가설을 제시하였다(SYN-E03-Q04,SYN-E04-Q04). REQ-M02/03은 기록 연속성과 학생의 선택·비입력 상태를 검토하는 후보이다. 기록량이나 합성 문구만으로 성찰/교육효과를 판단하지 않는다.
제안/보호/UX관점에서는 제안 근거와 교수자의 수정·유보를 보존하고, 역할별 직접 조회/쓰기와 갱신 실패·초점을 검증하는 조건을 제시하였다(SYN-E04-Q05,SYN-E07-Q06,SYN-E06-Q07). 이에REQ-M04–07을 제안 이력·오류·권한·사용성의 기술/과업 검증 후보로 연결하였다. 실제AI성능이나 개인정보 보호 체계의 완성을 입증한 것은 아니다.

라. 관점 차이·개발 의존관계·실증 미실시 범위
모의 교육과정/보건 관점의 규정 확정 요구와ICT융합 관점의 탐색 가능한 대안은 ‘제약에 따른 판정’과 ‘학습을 위한 탐색 제안’을 구분할 필요성을 드러내도록 구성하였다. 상담 관점의 기록 선택과 정보보호 관점의 접근/보관 경계는 공유를 많이 할수록 좋다는 가정을 제한한다. 기술과UX관점의 갱신/재조회 문제는 데이터 일관성과 사용자 초점/입력 보존을 함께 시험하는 가설로 연결된다. 이 차이는 실제 패널 토론에서 관찰한 불일치나 합의 결과가 아니다.
개발 선행순서는 자료/규정·접근 범위 확인→상담/목표/성찰 저장·재조회→제안/교수자 판단 이력으로 가정하고, 사용성/검증은 전 단계에서 병행한다. 이는 모의문서 출현 빈도에 따른 요구 순위가 아닌 연구자의 의존관계 가설이다. 실제 규정·사용자 요구·제품 조건이 확보되면 수정/기각해야 한다.
이번에 확인한 것은9개모의문서·72응답·8초기범주·8설계후보의 작성·추적/집계이다. 실제I/C설문이 없으므로Borich/LF·t검정·CVI·포화도·합의율·만족도·교육효과를 산출하지 않았다. 실제 요구분석 일정과 전문가 평가는 미완료로 유지한다. 전체 원문/코딩은research/data/synthetic-expert-scenarios-v1.json과synthetic-expert-analysis-v1.json, 방법은research/02-methods/synthetic-expert-protocol.md, 모의분석/반례는research/03-results/synthetic-expert-needs-analysis.md에 보관하였다.
