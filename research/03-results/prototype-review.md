# 기존 교수자용 대시보드 사전 검토

## 기록 정보

- 검토일: 2026-10-23 (한국시간)
- 대상: https://micro-degree-student.vercel.app/
- 화면 제목: TU 교수자용 학습설계 어시스턴트
- 개발 목적: 교수자 또는 교육과정 관리자가 학생의 자기설계 모듈형 교육과정 이수 현황을 확인하고 상담·컨설팅을 지원하는 대시보드. 연구자의 설명에 근거함.
- 검토 수행: Codex를 활용한 공개 화면·주요 상호작용·공개 클라이언트 코드의 기술적 사전점검
- 현재 판단: 연구의 교수자용 초기 프로토타입으로 활용 가능한 후보. 최종 산출물의 완성도, 전문가 타당성, 사용자 수용도 또는 교육적 효과가 검증된 상태는 아님.
- 연구자의 개발 시점, 개발 도구·원본 소스 버전, 사용 데이터의 출처와 실제 운영 여부는 추가 확인 필요.
- 검토 대상 공개 번들: https://micro-degree-student.vercel.app/assets/index-BVt3XIGK.js
- 위 주소는 검토 당시 배포본의 식별 정보다. 원본 소스의 커밋, 배포 ID 또는 무결성 해시를 확보한 보존본은 아니며, 추후 배포로 변경·삭제될 수 있음.

## 범위와 한계

격리된 브라우저에서 대시보드, 학생 관리, 개별 학습·진로 상담, 클래스 네트워크, 모듈 통계와 학생 상세 화면을 확인했다. 모듈 필터·페이지 전환·상세 열기·상담 일지 버튼의 동작을 점검하고 공개 JavaScript에서 관련 로직을 대조했다.

실제 학생 정보의 수정, 상담 기록 저장 또는 메시지 전송은 수행하지 않았다. 관리자 권한, 비공개 서버, 원본 저장소 전체, 실제 학사 데이터 연계와 운영 보안은 검증 범위에 포함하지 않았다. 버튼이 반응하지 않는다는 관찰은 확인한 배포본과 해당 동선에 한정한다.

화면 관찰과 코드 확인, 연구 활용에 관한 해석, 향후 실행할 평가 계획을 아래에서 구분한다. 실제 참여자를 모집한 사용자 평가나 전문가 평정은 실시하지 않았다.

## 확인한 기능과 연구계획서 대응

### F01. 교수자 전체 현황과 학생 탐색

- 관찰: 지도학생·이수율·상담 필요·상담 대기 카드, 학생별 이수 현황, 검색 입력 및 모듈별 분포가 표시된다.
- 관찰: 학생 관리 화면에서 모듈 필터를 적용했을 때 목록이 해당 모듈로 좁혀졌다.
- 연구 연결: 계획서의 교수자용 시각화 대시보드와 개별 학업 경로 파악을 위한 화면 설계에 활용 가능.
- 보완: 각 카드의 집계 범위·산식·기준일과 상담 우선순위 판단 근거를 정의해야 한다.

### F02. 학생 상세와 상담 준비

- 관찰: 대시보드 학생 행의 상세 버튼으로 평점·학점·모듈 진행률·평가 점수·상담 브리핑·상담 이력을 함께 보여 주는 화면이 열린다.
- 관찰: 상담 자료 출력 버튼과 출력용 화면 구성이 존재한다. 실제 PDF 파일의 생성·내용 정확성까지 검증한 것은 아니다.
- 연구 연결: 상담 전 정보를 종합하여 교수자의 판단을 지원하는 인터페이스와 대표 과업으로 활용 가능.
- 보완: 화면별 상세 진입 경로를 일치시키고, 실제 상담 자료의 근거·갱신 시점을 제공해야 한다.

### F03. 개별 상담 가이드와 협업 네트워크

- 관찰: 영역별 성취도, 진로 희망, 상담 주제, 코칭 문구와 클래스 네트워크가 표시된다.
- 코드 확인: 진도율 조건에 따른 사전 문구와 진로 값의 삽입 방식으로 상담 가이드의 일부가 구성된다.
- 코드 확인: 학생 관계와 네트워크 링크를 무작위로 생성하는 부분이 있다.
- 연구 연결: 상담 지원에 필요한 정보의 제시 방식과 설명 가능한 규칙 기반 안내를 검토할 수 있다.
- 보완: 생성형 AI 또는 학습된 모델의 사용·성능을 입증하는 근거는 확인되지 않았다. 연구에서는 실제 구현 방식과 적용 범위를 명시해야 한다. 관계 정보는 수집·산출 방법과 상담 활용 목적을 먼저 정해야 한다.

### F04. 모듈 운영 통계

- 관찰: 모듈별 GPA 추이, 역량 비교, 학생 분포, 상세 지표와 취업 사례 모달이 제공된다.
- 연구 연결: 교육과정 관리자의 정보 요구를 탐색하는 시각적 시제품으로 활용 가능.
- 보완: 고정·예시 수치와 실제 집계값을 구분해야 한다. 취업률·졸업생 사례의 사실성, 자료 출처 및 활용 가능 여부는 별도 검증 대상이며 연구의 실증 근거로 채택하지 않았다.

### F05. 상담 이력의 지속적 축적

- 관찰: 상담 이력과 메시지·상담 내용 입력창이 존재한다.
- 코드 확인: 상세 화면에 공통 예시 상담 이력 배열이 전달되며, 확인한 입력창·전송 버튼 부분에는 저장·전송 처리가 연결되어 있지 않다.
- 연구 연결: 상담 이력 통합 관리라는 계획서의 핵심 목표를 구현할 위치와 화면 구조는 확보되어 있다.
- 보완: 학생별 상담 식별자·일시·작성자·내용·수정 이력·후속 과제를 영속적으로 저장하고 다시 조회할 수 있어야 한다. 화면의 예시 이력을 실제 상담 데이터로 해석해서는 안 된다.

### F06. 자기설계와 성찰

- 관찰: 확인한 교수자 화면은 지정된 모듈의 진행률을 제시하는 데 중점을 둔다.
- 미확인: 학생이 모듈을 조합·변경하고 선택 이유와 성찰을 기록하는 동선은 확인되지 않았다.
- 연구 연결: 계획서가 강조한 자기설계 경로·성찰 데이터와 연결하기 위해 추가할 핵심 기능이다.
- 제안: 목표·모듈 조합·이수 조건·설계 변경 사유·상담 후 성찰을 연결하고 교수자의 피드백과 함께 이력으로 남긴다.

### F07. 인간-AI 협업과 검증

- 관찰: 상담 가이드를 보여 주는 화면은 있다.
- 미확인: 교수자가 제안을 수락·수정·기각한 근거와 학생의 최종 선택을 추적하는 기능은 확인되지 않았다.
- 연구 연결: AI 안내를 교수자 판단으로 환류하는 협업 모형을 구체화할 수 있다.
- 제안: 입력 근거 → 시스템 제안 → 교수자 검토 → 학습자 선택·성찰 → 후속 점검의 추적 가능한 흐름을 설계한다.

## 데이터와 기능 일관성 점검

- O01. 새로고침 후 학생 목록의 첫 행이 달라졌다. 공개 코드에서 학생·평점·학점·일부 성취 점수 및 관계의 무작위 생성 로직을 확인했다. 검토 당시 데이터는 모의 데이터로 취급한다.
- O02. 대시보드의 지도학생 수는 42명으로 고정 표시되지만 학생 관리에는 120개 행이 나타났다. 교수별 지도학생과 전체 학생을 구분한 것인지 설명이 없어 모집단·집계 연결 확인이 필요하다.
- O03. 평균 이수율·GPA 등 일부 요약 카드는 코드에 고정된 값을 표시한다. 실제 응답·학사 데이터에서 계산한 통계로 간주하지 않는다.
- O04. 학생 관리 하단은 1~10명 표시로 안내하지만 120개 행이 렌더링되었고, 2번 페이지 버튼 클릭 후에도 첫 행과 행 수가 바뀌지 않았다.
- O05. 확인한 동선에서 상단 상담 일지 작성, 상담 분석의 기록 시작, 메시지 메뉴 및 학생 관리 행의 상세 버튼은 기대한 새 화면·입력 폼을 열지 않았다. 대시보드 행의 상세 버튼은 작동했다.
- O06. 상담 가이드의 확인된 문구는 진도율 등의 조건에 따른 규칙 기반 표시다. 생성형 AI 호출이나 모델 검증 결과는 확인되지 않았다. 이 관찰로 비공개 서버 전체의 유무를 단정하지 않는다.
- O07. 모바일 폭 390px에서 문서 가로 폭은 390px로 확인했다. 전체 모바일 접근성과 모든 과업의 사용성을 검증한 것은 아니다.

## 연구에서의 위치와 서술 원칙

연구자가 제시한 기존 교수자용 대시보드를 초기 프로토타입으로 설정하고, 문헌·사례 검토와 교수자·학습자 요구분석을 통해 설계 요소를 재검토한다. 이후 상담 이력, 자기설계·성찰, 인간-AI 협업 기능을 보완하고 전문가 검토 및 형성평가를 실시하는 방향이 적절하다.

- 기존 개발물의 개발 시점과 연구의 각 단계는 실제 기록으로 확인한다.
- 기존 개발물을 사후 실시한 요구분석의 산출물로 소급하여 기술하지 않는다.
- 이번 사전점검은 기술적·설계적 검토이며 전문가 타당성 또는 교육적 효과 검증으로 대체하지 않는다.
- 무작위·고정 예시 수치는 실제 연구의 표본·통계·성과 수치로 사용하지 않는다.
- 기존 화면에서 재사용한 요소와 요구분석 후 새로 추가·수정한 요소를 구분해 대응표를 만든다.

## 우선 개선안

1. 버전과 데이터 고정: 원본 소스의 커밋·배포 ID·개발 도구·평가용 데이터 세트를 확정한다.
2. 이수 판단 기준 정리: 지도학생 범위, 모듈 이수율, 상담 필요 기준과 화면별 통계를 동일한 정의로 연결한다.
3. 상담 기록 완성: 상담 전 진단 → 교수자 판단 → 합의한 계획 → 기록 저장 → 후속 확인을 학생별로 연결한다.
4. 자기설계·성찰 추가: 모듈 조합, 선택·변경 사유, 상담 후 성찰과 피드백을 기록한다.
5. 협업 판단 추적: 시스템 제안의 입력 근거와 규칙·모델 버전, 교수자의 채택·수정·기각 이유를 남긴다.
6. 연구 근거 연결: 문헌·요구 항목 → 설계 원리 → 구현 기능 → 평가 과업으로 이어지는 대응표를 작성한다.

## 향후 평가 계획 제안 · 미실시

### 과업 A. 상담 대상 탐색과 설명

교수자가 고정된 가상 사례에서 상담이 필요한 학생을 찾고, 판단 근거와 데이터의 기준일·이수 조건을 설명하도록 한다. 과업 성공 여부, 소요 시간, 판단 근거의 정확성과 혼란 지점을 기록한다.

### 과업 B. 학습 경로 조정

학생의 목표·이수 조건·상담 이력을 바탕으로 모듈 조합 또는 다음 학습계획을 검토하도록 한다. 선택 이유의 설명 가능성과 실제 이수 조건 충족 여부를 확인한다. 관련 기능 구현 후 실시한다.

### 과업 C. 상담과 후속 점검의 연속성

상담 내용을 저장하고 다시 열어 이전 합의·설계 변경·학생 성찰을 확인하도록 한다. 저장 정확성, 누락, 재조회 가능성과 후속 조치의 연결 여부를 확인한다. 저장 기능 구현 후 실시한다.

교육공학·학사상담·시스템 설계 전문가의 검토와 실제 사용자 과업 평가는 구분하여 설계한다. 참여자 모집·자료 수집은 기관의 연구윤리 절차를 확인한 후 진행한다. 인원·도구·판정 기준·차수는 아직 확정하지 않았다.

## 후속 확인: 원본 저장소 식별

같은 날 연구자가 원본 저장소 주소를 제공하여 추가 확인했다. 교수자용 코드는 TU-Professor-Assistant 저장소의 tu-professor-assistant.zip 내부에서 식별했으며, 최상위에는 다른 학생용 화면 코드가 있다. 원본 저장소 커밋·ZIP 해시·배포 번들 해시와 대응 근거를 [원본 코드 확인](prototype-source.md)에 기록했다. 배포 소스 커밋과 Vercel 연결 설정까지 확인한 것은 아니다. 위 사전 검토 당시의 미확인 항목은 이 후속 확인 범위에서 보완한다.
