# 연구 완성 일정표와 보고서 진행 상태의 연계

2026-10-28 사용자 요청에 따라 일정표를 공유 증빙 상태에 연결했다. 최종보고서 본문은v0.8을 유지하며 이번 변경만을 위해 원고 버전을 올리지 않았다.

## 어디에서 확인하는가

https://project-b-lemon.vercel.app/index.html 상단의 공유 연구 현황에서 현재 원고 버전·집필 상태·증빙 확인 시각·실제 참여자 수·완료된 준비 산출물과 근거 링크를 확인한다. 월별33개 일정에는 예정·진행 중·선행 조건 필요·완료·증빙 확인 필요를 표시한다. 다음 마감과 기한 경과는 한국 달력 날짜로 계산한다.

문항 전체 문구를 작성한 일은 완료 산출물로 표시하지만, ‘설문 도구 개발’ 일정에는 타당성 검토까지 포함되어 있으므로 진행 중이다. 가상LF그림은 개발 검증 산출물이고 실제LF요구분석 일정은 미완료이다. 누적 원고가 있어도 연구보고서 전체 완성·제출 과업을 자동 완료하지 않는다. 따라서 완료 산출물 수와 원래 일정33개 전체의 완료율은 다를 수 있다.

## 공유 상태의 기준과 갱신 절차

1. Google Docs 최종보고서/수행보고와 현재Git·연구tasks/evidence를 먼저 읽고 사용자 편집을 보존한다.
2. research/progress-source.json의basedOnReportVersion·reportStatus·reportNote·실제 참여자 수·과업/산출물의상태·이유·근거 링크를 갱신한다. reviewedAt은실제로증빙을확인한한국시간이다. 승인·조사·효과를계획만으로완료처리하지않는다.
3. node scripts/sync-research-progress.cjs를 실행한다. 현재report manifest와기준버전이다르면중단하므로원고변경후상태를다시검토해야한다. 완료표시에는근거링크가필수이며일정ID·상태값·근거파일을검사한다.
4. 생성된research/progress.json·원본상태·원고/증빙의수정분을작업브랜치에커밋하고main에반영·배포한뒤운영일정표를확인한다. 관련변경과발행확인을당일수행기록에남긴다.
5. 화면은진입시·다시활성화될때·활성화중60초마다공유파일을읽는다. ‘최신상태확인’으로수동갱신할수있다. 읽기에실패하면마지막으로성공한상태와오류를함께표시한다.

구글독스의직접편집을수초단위로실시간수집하는별도서버연결은아니다. 이대화의연구/보고서작업과정기실행이문서/증빙을대조해공유상태를발행하고,일정표가발행본을다시읽는다. 구글독스수동편집은다음작업·정기확인시대조하여반영한다.

## 개인 기록 보존

기존nrf-b-2026-checks의브라우저체크값은개인메모로유지한다. 개인메모는공유증빙완료율과상태를바꾸지않으며다른기기로자동전송되지않는다. ‘개인메모초기화’는이브라우저기록만초기화하고공유기록은보존한다. 공유일정의완료여부는개인체크나기한경과로판정하지않는다.
