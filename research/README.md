# 연구 문서 관리

이 폴더는 선정 연구계획서에 근거한 연구 원고의 기준본입니다. 월별 일정은 기존 일정표에서 관리하고, 본문과 근거·판단·남은 과제는 이곳에 축적합니다.

## 목차

1. [연구 개요](01-overview/README.md): 목적·연구문제, 범위와 계획 변경
2. [연구 방법과 수행](02-methods/README.md): 문헌·사례, 연구윤리, 설문·FGI, 분석 방법
3. [연구 결과](03-results/README.md): 요구분석 결과, 모형·설계 원리, 프로토타입, 타당성 검토
4. [논의와 활용](04-discussion/README.md): 논의·한계, 활용방안·성과 확산
5. [제출용 요약](05-summaries/README.md): 국문·영문 요약, 결과 개요·색인어
6. [참고문헌과 부록](06-references/README.md): 검증한 문헌, 증빙·AI 활용 기록

각 장에는 본문 문서와 `evidence.md`(근거 자료 목록), `tasks.md`(남은 과제)가 있습니다. 현재 문서는 계획서 기반 작성 틀입니다. 실제 연구 결과는 수행·확인 후 기록합니다.

## 작업 흐름

1. 최신 `main`을 기준으로 구체적인 작업 브랜치를 만듭니다.
2. 관련 본문과 근거·남은 과제를 함께 수정합니다.
3. 계획·수행 사실·분석·해석을 구분해 검토합니다.
4. 문서 목록 변경 시 `node scripts/build-research-index.cjs`를 실행합니다.
5. 작업 내용을 커밋하고 검토한 뒤 `main`에 병합합니다. 원격에 남긴 작업 브랜치는 자동 삭제하지 않습니다.
6. `main`을 GitHub에 푸시하면 Vercel이 반영한 문서를 웹앱에서 읽을 수 있습니다.

브랜치 예시:

- `research/literature-review`: 문헌·사례 검토
- `research/survey-design`: 설문·FGI 도구와 연구윤리 절차
- `research/needs-analysis`: 요구분석
- `research/prototype-design`: 설계 원리·모형·프로토타입
- `research/expert-validation`: 전문가 검토·수정
- `research/report-revision`: 종합 보고서 검토

위 이름은 향후 작업 예시입니다. 실제 작업을 시작할 때 생성하며, 목차별 장기 분리 브랜치는 두지 않습니다. 이번 문서 구조 정리 작업은 `research/workspace-structure` 브랜치에 기록합니다.

## 본문과 웹앱

- [웹앱 저장소 문서 화면](https://project-b-lemon.vercel.app/research.html#repository)은 `index.json` 목록에 있는 Markdown 문서를 읽습니다.
- 본문 문서의 `report-body:start`와 `report-body:end` 표식 사이에 보고서로 사용할 원고를 작성합니다. 표식은 유지합니다.
- 웹앱 보고서 작성 화면에서 **저장소 기준 본문 불러오기**를 눌러 해당 본문을 개인 초안으로 가져올 수 있습니다. 기존 초안은 확인 후 교체하며 이전 본문을 버전으로 보관합니다.
- 웹앱에서 편집한 개인 초안은 브라우저에 저장됩니다. **보고서 내려받기**로 원고를 내보내 검토 후 해당 저장소 문서에 반영합니다. 자동 양방향 동기화 기능은 없습니다.
- 최종 제출 전 재단 지정 서식과 대조합니다.

## 근거와 자료

- 인용 근거에는 출처 URL/DOI, 쪽·문단·표, 확인일과 확인 상태를 남깁니다.
- 참여자 식별자료, 원본 동의서, 비공개 원자료는 이 공개 저장소에 올리지 않습니다. 승인된 별도 보관소에서 관리하고 익명화된 요약과 위치만 기록합니다.
- 계획서의 참고문헌을 원문 검증 없이 확정된 참고문헌으로 간주하지 않습니다.
- AI를 사용했다면 도구·모델·일자·활용 범위와 인간 검증을 기록합니다.
