# 요구분석 설문 문항의 설계·코드북·분석 연결

버전 needs-1.0-proposal / 2026-10-27 / 전체 문구 작성 완료, 타당화·수집 미실시. 이전 ‘12개 기능 이름만 있는 코드북’을 구체적인 교수자/관리자용·학생용 I/C 문구로 확장했다. 기존 응답을 수정하거나 가상 응답을 실제 자료로 만든 것이 아니다.

## 측정하려는 개념

분석 목적은 기능의 필요수준과 현재 환경의 지원수준 차이를 확인하는 것이다. I는 향후 필요성, C는 현재 지원 정도이며 만족·개인 역량·성적·AI 정확도·학습효과를 측정하지 않는다. 기능들은 서로 다른 과업을 대표하므로 하나의 잠재 특성을 측정하는 단일 척도나 총점으로 간주하지 않는다. 내적 일관성이 높다는 이유만으로 불필요한 기능을 합치거나 삭제하지 않는다.

기준 기간은 응답일 기준 이번 학기, 기준 환경은 현재 학교의 학사시스템·문서·상담 절차 전체이다. 신규 연구용 프로토타입 사용 후 만족도와 혼합하지 않는다. 필요수준과 현재수준의 기준이 역할마다 달라지지 않는지 인지 면담/예비 이해도 검토에서 확인한다. 현재 기능이 없다는 것을 알면 C=1, 존재 여부나 경험을 모르면 DK/NE로 구분한다.

## 구성과 응답 형식

두 설문 모두 배경6문항, 핵심12쌍(각 I/C 총24수치 응답 가능), 우선 선택1문항, 개방형3문항으로 작성했다. 참여/대상 확인은 별도이다. 개방형O01을 기능 목록 전에 묻고 O02/O03은 누락 기능·우려/조건을 묻는다. 시행 시간은 아직 측정하지 않았다. 배경 변수를 구체적 학과명·성명·학번과 결합하지 않으며 소집단 재식별 가능성을 점검한다.

I:1전혀 필요하지 않다–5매우 필요하다. C:1전혀 지원되지 않는다–5충분히 지원된다. 3은 보통이며 ‘모름’의 대체값이 아니다. 각 문항마다 DK(판단하기 어려움),NE(경험 없음),RF(응답하지 않음)을 허용한다. 두 값 중 한쪽만 결측이어도 Borich/LF의 해당 쌍에서는 제외하되, 문항별 수치 응답과 결측 사유 분포는 별도 보고한다. 배경·자유응답·우선 선택은 요구도 산식에 넣지 않는다.

## 전체 문항의 위치

교수자·관리자용: survey-faculty-v1.md, 학생용: survey-student-v1.md. 두 문서에 안내·모든 배경/핵심/우선/개방형 문구·보기와 응답란을 수록했다. 기계 판독 기준본은 research/data/needs-instrument-v1.json이며 두 설문 핵심 문구는 이 기준본에서 생성했다. 보고서16절 부록에도 두 설문 전체를 수록한다.

## 내용·이해도 검토와 변경 관리

연구자가 관련성·명료성·단일 개념·대상 적합성·I/C 구분·결측 안내의 관점에서 검토를 준비하고, 실제 전문가 선정·심의/동의·수집 절차를 확정한 후 검토를 실시한다. 문항을 자신의 말로 설명하게 하여 ‘현재’의 대상과 ‘없음/모름’의 구분을 확인한다. 두 문항이 같은 기능으로 해석되거나 복합 요구로 읽히면 분리/수정 이유를 남긴다. 검토 인원·차수·척도·수치 기준은 실제 설계 확정 전 임의로 정하거나 완료로 표시하지 않는다.

문항 문구·응답 보기·기준 기간·역할 대응이 바뀌면 도구 버전을 올린다. 원문→수정문→이유→근거/검토일→재검토 여부를 기록한다. 과거 v0.7의 빈 검토 패킷은 준비 이력으로 보존하며 새로운1.0 문구에 대한 실제 검토 결과는 아직 없다.

## 분석 계획과 실행 전 확인

1. 공식 모집단 현황과 역할별 표집틀·모집 경로·기간을 확정한다. 합성학교1,000명이나 선행논문의 참여자 수를 표본수 근거로 가져오지 않는다. 인원은 실제 접근 가능 모집단·목표 분석·정밀도/검정력·응답률 검토 후 정한다.
2. 역할별 문항의 유효 쌍수 n, I/C 평균·분포, D=I−C와 결측 사유를 제시한다. 각 문항의 동일 완전 쌍을 사용하여 Borich 평균가중차이=M(I)×M(D)를 산출한다. LF는 x=M(I),y=M(D),축 절단선은 해당 역할의 포함 문항 평균을 같은 문항 가중으로 계산한다. 경계·동점·높은 결측률과 포함 문항 변동을 명시한다.
3. 대응표본 t 검정은 집단 간 비교가 아니라 같은 응답자의 I/C 쌍 비교이다. 차이값 분포·이상치·독립성 등 검토와 신뢰구간/효과크기·다중검정 처리 계획을 실제 분석 전 확정하고, 적용 부적합이면 대안/민감도 분석을 기술한다. 현재 개발 계산기는 통계량 산술만 검증했으며 p값·추론 절차는 미실행이다.
4. F와S를 먼저 분리한다. R10/R12는 과업 관점이 달라 직접 평균 차이 비교를 하지 않는다. 나머지 문항도 의미 동등성·표집 적합성 확인 없이 합치거나 대학 전체 일반화하지 않는다. 중요도 상위3선택은 보조 빈도, 개방형은 비식별 의미단위로 코딩하고 기존 문항에 없는 요구를 별도 코드로 보관한다.
5. Borich/LF의 중복 후보는 요구상 우선순위 후보이다. 질적 사유·학사 규정·데이터/보안·구현 의존성과 함께 검토한 결정표를 남기고 실제 분석 없이 최우선 기능을 확정하지 않는다.

실제 응답 자료 계약은 instrument_version, respondent_id(비식별 연구키),role,item_id,importance,current,importance_missing_reason,current_missing_reason,reference_period,collection_wave를 포함하도록 제안한다. 동의/연락처 원장은 별도 비공개 보관한다. 현재 scripts/analyze-needs.py는 synthetic=true 개발 fixture 전용이며 실제 자료를 바로 투입하지 않는다. 실제용 어댑터·접근 통제·필드 검증을 별도 구현/확인한 후 연결한다.
