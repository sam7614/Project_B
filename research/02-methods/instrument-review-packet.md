# 요구조사 문항 검토 패킷 — 미실시 초안

현재 검토할 전체 문항은 needs-instrument-design.md와 survey-faculty-v1.md / survey-student-v1.md의 needs-1.0-proposal이다. 아래 빈 검토표는 이 원문과 함께 사용한다. 이전 기능 후보 명칭과 달리R03은 공식 기준의 출처 확인, R09는 AI 사용 경험을 전제하지 않는 제안 근거, R10/R12는 역할별 관점의 차이를 명시했다. 실제 검토 의견·평정은 여전히 없다.

2026-10-27 저녁 작성. 오전의12문항 코드북을 후속 검토할 수 있도록 검토 절차·빈 기록 양식·수정 기준을 준비했다. 전문가 검토자·실제 응답자는 모두0명이다. 모집·심의·평가를 실시한 기록이 아니며 검토 결과나 CVI 값을 채우지 않았다. 문항 초안은 [요구조사 코드북](needs-codebook-draft.md)을 따른다.

## 검토 목적과 순서

검토의 목적은 중요도 I와 현재 지원수준 C의 의미가 교수자·학생에게 일관되게 전달되는지, 한 문항이 한 기능을 묻는지, 구현 전 목표 기능을 현재 경험처럼 묻지 않는지 확인하는 것이다. 이는 만족도나 학생 역량 척도의 검증이 아니다.

1. 연구자가 대상 집단·표집·검토자 전문성/역할·인원·이해충돌·모집 및 기관 절차를 확정하고 비공개 기록 위치를 정한다. 현재 인원을 임의 확정하거나 승인으로 간주하지 않는다.
2. 검토자에게 코드북 버전·기준 환경·기준 기간·필요/현재 지원수준 정의를 함께 제공한다. 기준 환경/기간의 구체 값은 아직 미확정이므로 발송 전에 채운다.
3. 문항마다 관련성·명료성·단일 개념·대상 적합성을 각각 검토하고 수정 이유·오해 가능성·누락 기능을 적는다. 아래 빈 양식에는 응답값이 없다.
4. 역할별 소수 인지 면담/이해도 확인을 계획할 수 있으나 참여자 모집과 자료 수집은 기관 절차·동의 확인 후 별도로 실시한다. 아직 면담한 사람이 없다.
5. 연구자가 원문→제안→채택/수정/보류 이유를 남기고 새 도구 버전을 정한다. 수정 문항의 재검토 필요 여부를 기록한 뒤 실제 조사 사용 여부를 결정한다.

## 미리 점검할 의미상의 위험

- R02: 선택한1개 모듈의 남은 항목과 졸업요건·다중 모듈 학점 인정은 다르다. 현재 지원 환경의 범위를 제한하여 설명해야 한다.
- R03: 출처와 버전이 한 기능으로 이해되는지 확인하고 두 개념으로 해석하면 분리 여부를 판단한다.
- R04–R08: 화면/합성 필드의 존재와 기록의 실제 저장·재조회·상담 연속성을 구분한다. 사용한 적 없는 기능에는 경험 없음이 가능해야 한다.
- R09/R10: 현재 AI 추천을 운영한 경험으로 읽히지 않게 목표 기능을 설명한다. 현재 대체 수단의 지원수준과 목표 AI 기능의 필요성을 비교하는 의미가 집단별로 달라지는지 확인한다.
- R12: 역할 통제가 미구현인 공개 합성 데모를 기관 개인정보 보호 체계로 평가하지 않도록 안내한다. 교수자 내부 기능을 모르는 학생의 결측을 허용한다.

## 수정 결정 기록 양식

기록 ID / 도구 버전 / 문항 ID / 검토일 / 비식별 검토자키 / 원문 / 제안 / 결정(유지·수정·분리·보류) / 근거 / 새 문구 / 재검토 필요 / 연구자 확인일을 비공개 원장에 기록한다. 공개 저장소에는 개인의 성명·소속·연락처·음성·동의서·자유서술 원자료를 올리지 않는다. 현재는 빈 양식만 준비했다.

## 조사 전 통과 조건

- 기준 환경·기간·역할별 안내·모름/결측 처리와 문항 의미를 연구자가 확정한다.
- 검토의 실제 실시·수정 결정과 기관 절차/모집·동의 증빙을 확보한다.
- 표집·제외·역할별 분석·가정 검토·효과크기·다중검정 처리 계획을 실제 자료를 보기 전에 문서화한다.
- 현재 계산기는 synthetic=true만 받으므로 실제 조사 자료용 비공개 어댑터와 접근·철회·보관 절차를 별도로 구현한다.
