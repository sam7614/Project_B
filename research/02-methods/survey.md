### 가. 요구분석의 사전 자료와 분석 단위

본 연구에서 요구는 화면에 추가하고 싶은 기능의 목록 자체가 아니라, 사용자가 수행해야 할 학업 설계·상담 과업과 현재 지원 환경 사이의 불일치이다. 따라서 설문에 앞서 무엇을 판단해야 하는지, 어떤 규정을 적용해야 하는지, 누가 판단과 기록의 책임을 갖는지, 실제로 어떤 정보를 사용할 수 있는지를 명시한다. 사전 자료는 규범적 기준, 현행 과업과 사용 맥락, 기술적 자료 구조, 이해관계자의 경험을 구분하여 구성한다. 연구자가 예상한 불편과 실제 사용자에게 확인된 요구를 동일하게 취급하지 않는다.

선정 계획서10–11쪽은 문헌·사례·예비조사와 최종 사용자인 교수자·학습자의 요구를 설계 요소에 연결하도록 하고,14쪽은 도구 개발·기관 절차·설문과FGI·분석의 순서를 제시한다. 이번 보완에서는 해당 쪽을 다시 읽어 사전 자료의 범위를 정리했다. 문서에 과거 계획 월이 적혀 있다는 이유로 실제 승인·조사가 이루어졌다고 보지 않는다.

분석 단위는 ‘사용자 역할×의사결정 과업×필요 정보×현재 수단×제약’이다. 예를 들어 미이수 항목 확인은 교육과정 기준과 학생 이수 행을 비교하는 과업이다. 현재 프로토타입이 이 비교를 표시할 수 있다는 사실은 교수자의 실제 시간 부담이나 학생의 요구 강도를 입증하지 않는다. 전자는 기술 검증, 후자는 별도 조사 자료로 다룬다.

### 다. 자료 분석·문항 도출의 연결

PR01·PR02·PR05·PR06·PR07은 현재 확보한 범위에서 문항의 잠정 근거를 제공한다. PR03·PR04·PR08의 현장 자료는 조사 이전에 확보하거나 미확보 사유와 가능한 해석 범위를 남긴다. 실제 상담 자료를 요청할 때에는 먼저 빈 양식과 업무 지침으로 구조를 파악하고, 식별 가능한 과거 상담 기록이나 성적 원장을 공개 저장소로 옮기지 않는다.

각 사전 자료의 등록 항목은 자료ID, 제목/기관, 적용연도·버전, 확보일, URL 또는 비공개 보관 위치, 확인한 쪽/절, 추출한 사실, 연구자의 해석, 연결 문항, 미확인 사항이다. 실제 사람의 의견에는 수집 방식과 동의 범위를 별도로 기록한다. 동일 자료라도 원문 사실과 설계 가설은 별도 칸에 작성한다.

분석 흐름은 ‘사전 자료 등록→과업/문제 진술→요구 후보→문항I/C→내용·이해도 검토→실제 조사→요구도/질적 분석→기능 결정’이다. 예비 면담에서는 먼저 기존 과업과 어려움을 묻고, 이후 기능 설명과 화면을 제시해 추가 의견을 확인한다. 화면을 먼저 보여 주어 연구자의 설계에 맞춘 답을 유도하는 위험을 줄이기 위한 본 연구의 절차적 선택이다(Karademir et al., 2024).

한 기능이 필요하다는 응답만으로 구현 우선순위를 확정하지 않는다. 역할별 중요도·현재 지원의 차이, 질적 이유, 규정·자료 가용성, 보안과 구현 의존성을 함께 검토한다. 요구 우선순위와 구현 선행 순서는 별도 열로 보관한다. 근거가 부족하면 ‘추가 확인’으로 남기고 가상 응답을 보충하지 않는다.

R01–R03은 공식 이수 기준과 현재 자료의 연결, R04–R06은 목표·변경·성찰, R07–R08은 상담 피드백과 후속 관리, R09–R12는 제안 근거·교수자 판단·오류·접근 범위를 다룬다. 현장 자료가 없는 항목은 연구계획·문헌·프로토타입에 기초한 잠정 후보이다. 자료ID→기능 개념→문항→과업의 대응표와 각 한계는 needs-instrument-design.md에 보관한다.

### 라. KCI 개발 연구의 벤치마킹과 적용 범위

웹 기반 교육지원 시스템 개발 방법을 검토하기 위해2026년10월27일 KCI에서 대시보드·프로토타입·요구분석 등의 검색어와 제목/DOI로 관련 연구를 확인하였다. 전체 검색 건수나 체계적 고찰·질 평가 점수는 산출하지 않았다. ‘완성도 있는 개발 절차’는 사전 자료–요구–설계–평가의 연결을 참고할 수 있다는 의미로 사용한다.
임철일 등(2024)은 문헌·사례와 사용자 요구를 설계원리에 연결한 사례로, 나은창(2026)은 현존자료와 과업 분석을 대학 대시보드 개발에 연결한 사례로 참고하였다. 임수진(2024)은 역할·규칙·도구의 실제 사용 맥락, 임은선 등(2025)은 설계와 전문가 검토·현장 적용의 구분, 김기덕과김정겸(2025)은 기능·플랫폼·인프라의 범위 구분에 참고하였다. 원 연구의 대상·표본수·효과나 척도 타당성을 본 연구에 이전하지 않았다.
해외 비교에서는Karademir 등(2024)의 문제 탐색→아이디어→템플릿 검토와Mohseni와Masiello(2026)의 면담→설계→개발/사용성→적용 절차를 참고하였다. 사전 자료와 요구, 설계 결정의 출처를 추적하되 시스템 화면을 보기 전의 어려움과 화면을 본 뒤의 개선 의견을 분리한다.
KCI5편은 등재·서지·공개 초록 범위, 해외2편은 공개 출판사 본문을 확인하였다. 학회PDF 파일을 확보하지 못한KCI문헌의 세부 설문을 읽었다고 주장하지 않는다. 출처와 실제 읽은 범위는 needs-analysis-prerequisites.md 및 research/data/needs-benchmark-sources.json에 기록하였다.

### 마. 설문 개념·구성과 전체 문항

설문은 needs-1.0-proposal로 자체 작성한 교수자·교육과정 관리자용과 학생용 두 종류이다. 각 설문은 배경6문항, 기능12쌍(I/C 총24수치 응답 가능), 우선 선택1문항, 개방형3문항으로 구성한다. 참여·대상 확인은 별도이며 문항 원문·보기·응답란은16절 부록A·B에 모두 수록하였다. 원 척도 복제/번안이나 검증된 척도의 채택이 아니다.
필요수준 I는 향후 기능의 필요성, 현재 지원수준 C는 응답일 기준 이번 학기에 학교의 기존 학사시스템·문서·상담 절차가 제공하는 지원 정도이다. 신규 프로토타입 만족도나 개인의 능력·성적을 묻지 않는다. I는1전혀 필요하지 않다–5매우 필요하다, C는1전혀 지원되지 않는다–5충분히 지원된다로 응답한다. 기능이 현재 없음을 알면C=1, 모름·경험 없음·응답 거절은DK/NE/RF로 구분하며0이나3으로 대체하지 않는다.
R03은 복합 해석을 줄이기 위해 공식 기준의 출처 확인으로 좁혔고 버전은 자료의 메타데이터로 관리한다. R09는AI 추천 경험을 전제하지 않는 경로 제안의 근거, R10은교수자의 기록/학생의 확인, R12는역할별 정보 접근 범위로 구체화하였다. R10/R12는직접적인 집단 평균 차이 비교를 하지 않으며 나머지 대응 문항도 의미 동등성 확인 없이 집단을 합치지 않는다.
기능 목록 제시 전O01에서 이번 학기의 어려움을 먼저 묻고, 이후I/C문항과 누락 기능·우려 조건을 제시한다. 우선 선택P01은 최대3개 선택 빈도의 보조 지표이며Borich/LF를 대체하지 않는다. 개방형 응답은 식별정보를 제거한 의미단위로 코딩하고 목록에 없는 새 요구를 별도로 보관한다.

### 바. 문항 검토·표집·분석 전제

배포 전에 기준 환경·기간·역할별 문구와 모름/없음의 구분을 내용 검토·예비 이해도 점검으로 확인한다. 검토자는 관련성·명료성·단일 개념·대상 적합성을 검토하고 원문→제안→수정 결정의 이력을 남긴다. 검토자 수·차수·정량 판정 기준과 기관 절차는 실제 설계 확정 전 완료로 표시하지 않는다. 현재 조사 응답자·전문가 검토자·평가 참여자는 모두0명이다.
표집은 실제 공식 현황과 모집 경로·목표 분석·정밀도/검정력·응답률 검토를 바탕으로 확정한다. 합성학교 규모나 선행연구의 참여 인원을 그대로 표본수로 가져오지 않는다. 모집·동의·자료 보관/철회·수집 도구의 계정/IP·접근권한과 기관 심의/면제 여부는 확인 후 기록한다.
